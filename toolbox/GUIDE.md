# Agent 制作工具箱

先从页面的学习目标、输入、可操作动作、反馈和依据确定一个最小可用路径，再选择工具。工具按需要进入该页面，不为新页面默认加载全部库。

## 新专题

`npm run site:new -- <slug> "<title>" "<description>" <group>` 在 `MOLNOTES_CONTENT_DIR` 生成专题。`site.json` 提供标题、简介、排序、分组 `group`（取值见 [内容手册](../docs/content.md)）与可选的 `label`；根层 `content.json` 提供章节（含各章用到的全站术语名 `terms`）、预测、练习、来源与块序列；`static/` 存放资源。提交后用 `npm run content -- publish` 发布；契约见 [内容手册](../docs/content.md)。

专题只提供数据，所有交互由共享层渲染。一章是一个块序列，作者决定讲什么、先预测什么、拿哪些证据、按什么顺序；每种块对应共享层的一个组件和一份由 `shared/topic-content.ts` 在发布与挂载时校验的字段契约。正文、图表与实验从打开章节起可见。每道预测只在作答后显示自己的答案与解释；一章可以有多个 `prediction` 块，第一个的记录 id 默认是章节 id，其余自带 `id`。章末的判断练习、原文区、阅读指引、本章来源与记录由章节体自动接在块序列后，块里已显示的题与摘录不重复。大数据（机理帧、路线步骤、表行、曲线点）放在顶层 `data` 里按键命名，块以字符串引用。需要宽屏的章节设置 `layout: "wide"`。

### `problem` 开放题

必填 `id`、`lang`（`en` 或 `zh`）、`answer: { text, origin, basis }`；`prompt` 与 `parts` 至少有一个。`prompt` 与 `answer.text` 接受非空字符串或非空字符串数组，内联来源与术语标记沿用 paragraph；`origin` 为 `book`（书内答案）或 `ai`（AI 答案），`basis` 为依据文字。可选 `label`（题号）、`source`（出处）、`task`（任务与预计用时）、`parts`（非空字符串数组，按 a、b、c 显示）、`evidence`（专题顶层 excerpt id 数组）。`id` 在全专题内与预测题共同唯一。未知字段被拒绝。

答题框先保存自己的答案，点击后才渲染参考答案与依据，自评「会 / 不会」可改。服务端记录 `problems[id]: { response, rating? }`，`response` 最多 20000 字，`rating` 为 `know` 或 `unknown`；空答案且未自评的条目不保存。自评「不会」进入复习页与首页错题计数，改评「会」后移除。题面不进入搜索。

`prediction` 的可选 `source` 为非空出处文字，与开放题使用同样的出处行；可选 `evidence` 为专题顶层 excerpt id 数组，作答后显示原文摘录，与单个 `excerpt` 去重。选择题的 `optionExplanations` 与选项一一对应，作答后逐项展示并标出正确项与自己的选择。答错的预测题进入错题本，改对后移除。

专利数据块：

| 块                  | 字段                  | 数据与行为                                                       |
| ------------------- | --------------------- | ---------------------------------------------------------------- |
| `source-pages`      | `source`              | 引用 `data.sources.<id>`；原页、矩形定位、段落与 OCR 检索        |
| `record-collection` | `collection`          | 引用 `data.collections.<id>`；筛选、排序、分页、详情、比较与笔记 |
| `claims`            | `set`                 | 引用 `data.claims.<id>`；依赖列表、片段、对比与化学模式匹配      |
| `sar-cases`         | `cases`、`collection` | 引用 `data.sarCases.<id>` 与记录集合；案例并排及分档交叉计数     |
| `synthesis-network` | `network`             | 引用 `data.synthesis.<id>`；连接步骤、分支、程序证据与路线比较   |

`data.sources.<id>` 为 `{ title, pages, size, image, text, paragraphs }`：`size` 必填，为 PDF points 单位的正数 `[width, height]`（例如 Letter `[612, 792]`、A4 `[595, 842]`）；`image` 是本专题 `static/` 下带 `{page}` 的绝对路径，`text` 是 OCR 字符串数组 JSON 的绝对路径，`paragraphs` 把 `"0005"` 这样的段落号映射到页序。原页引用 `{ source?, page, end?, rect?, asset? }` 的 `rect` 是所引用来源 `size` 范围内的 PDF points 坐标 `[x0,y0,x1,y1]`，`asset` 是片段图的绝对路径。省略 `source` 时继承记录来源；字段定义上的原页引用应显式指定来源。原页路由 `/sources/pages/<n>?source=<id>&rect=...`，检索路由 `/search?q=...&source=<id>`；检索框也解析 `[0005]`，正文中的已知段落号可点击。

`data.collections.<id>` 为 `{ title, route, fields, scales, pins?: { max }, export?, records }`。`route` 不带起始斜杠，可为 `examples` 或 `synthesis/intermediates`；列表 `/<route>`、详情 `/<route>/<id>`、比较 `/<route>/compare`。章节已有列表路径时由章节渲染块，附加详情由共享路由注册。多个来源时显示来源筛选与比较分组，来源名称取 `data.sources`。`id` 是正整数或仅含字母、数字、下划线、连字符的字符串，同一集合内唯一。

字段定义为 `{ key, label, kind, filter?, sort?, scale?, ref? }`。`kind` 支持 `text`、`number`、`tags`（字符串数组）、`smiles`（结构字符串）、`grade`、`ref`（原页引用）、`link`（站内路径）、`body`（`{ url, key }` 指向静态 JSON 的字符串正文）。`grade` 的 `scale` 指向本集合的 `scales.<id>`，定义 `{ bins: [{ value, label }], blank, dash }`；分档按 bins 顺序排序，未列字段、空字符串与 `"--"` 分别保留，缺失排在末尾。`filter` 启用对应文字、标签、分档或数值区间控件；结构列提供 SMILES / SMARTS 子结构筛选。筛选与排序、分页、视图写入 URL：`q`、字段 key、`<key>.min/max`、`source`、`sort`、`order`、`page`、`view`、`substructure`；`ids=1,2` 限定记录集合。CSV 导出当前结果并保留 SMILES 和缺失状态。

每条记录为 `{ id, source, ...字段值, refs?, notes? }`。`refs` 的键是目标 collection id，值是该集合 id 数组；保留键 `claims` 指权利要求 id。`notes` 为 `{ field?, text, ref? }[]`，用来并列来源差异或解释未确认结构。`pins.max` 控制比较上限，超限提示并拒绝；逐条笔记与比较编号由网站记录 API 保存，写入失败显示重试入口。

`data.claims.<id>` 为 `{ source, claims: [{ id, title, group, text, note?, refs, children, segments, scope?, examples }] }`。权利要求 id 在专题内唯一，`refs` 与 `children` 是权利要求 id，`segments` 是带 `asset` 的原页引用，`examples` 引用 `data.collections.examples`。详情 `/claims/<id>`，对比 `/claims/compare?ids=a,b`；`scope: { smarts, note }` 给出作者核对的结构范围与简化说明。输入 SMILES 后返回 matched、not-matched 或 unmodeled，界面分别显示匹配所声明子结构、未匹配所声明子结构或未建立化学模式，并保留作者整理的实施例关联。SMARTS 发布时解析；化学匹配不等同于完整权利要求范围。测量、证据归类、连接合成及程序引用的字段和保守比较语义见 [Agent 研究契约](../docs/content.md#agent-专利研究记录)。

`data.sarCases.<id>` 是 `{ id, title, ids, area, change, finding, limit, claims }[]`，`ids` 引用块的 collection，`claims` 引用权利要求。案例 id 在专题内唯一，详情 `/sar/<id>`；结构、分档和原页并排，分档交叉计数可跳到对应记录集合。多个 SAR 块可分别引用不同案例集。

章节避免占用生成的详情、比较和检索路径。中性完整样本见 `tests/fixtures/content/sites/fable-patent/`；发布布局见 [内容手册](../docs/content.md)。

专题需要目录里没有的块时扩目录（`shared/topic-blocks.ts` 的契约、`src/ui/topic/blocks.ts` 的类型、`ChapterBlocks.vue` 的渲染分支，`lab` 新模型加进 `catalog.ts` 并写单测），不在 `sites/<slug>/` 下写组件。

发布到开发库后验证最重要的学习交互；共享代码使用中性样本运行浏览器测试。

## 共享界面层

共享界面层位于 `src/ui/`，经 `@ui` 导入。`/showcase/` 按同样方式组织，是各组件的参考用法。

- `mountApp(root, { base, routes })`：为示例页这类非专题应用创建路径路由并挂载，未知路径显示“页面不存在”。页面滚动在路径变化时回到顶部，只改变 query 时保留位置，带 fragment 时定位到对应元素。
- `TopicShell`：接收 `title`、可选 `subtitle`、`description`、`groups`。每组有可选 `id`、`label`、`open`（读者折叠前的默认状态，默认展开）、`items` 与子分组 `groups`；条目为 `{ to, label, number?, read?, bookmarked?, mistakes? }`，`to` 是专题内的路由路径；当前路径或其子路径对应的条目标为当前项。侧栏由笔记本与专题共用的 `SectionSidebar` 提供：可折叠分组、筛选框、键盘移动、桌面收起与手机底部抽屉。外壳另提供手机“目录”按钮和按目录顺序生成的上一节与下一节。`sequence` 可传入另一组条目作为上一节与下一节的阅读顺序，例如按读者选择的学习路径排列；`pager` 设为 `false` 可关闭上一节与下一节。
- `PageHeading`：接收 `title`、`eyebrow`、`summary`，默认插槽可放专题自己的说明。它设置文档标题；读者在专题内切换页面后，焦点移到新标题并向读屏软件通告。
- `UiDialog`：`v-model:open` 控制的模态弹窗，接收 `title`，提供关闭按钮、Esc 与点击遮罩关闭，关闭后焦点回到打开它的控件。
- `UiFigure` 与 `ImageViewer`：`UiFigure` 接收 `src`、准确的 `alt` 和可见的 `caption`，点击后以 `ImageViewer` 放大；查看器支持适应窗口、原始尺寸、缩放、拖动和加载失败提示。只需查看器时直接使用 `ImageViewer` 并传入 `src`、`alt`、`title`。
- `Formula` 与 `LineChart`：KaTeX 公式和 ECharts 折线图（`points` 单线，或 `series: [{ name, points, scatter? }]` 多线加散点读数与图例；`xDomain` / `yDomain` 固定范围），颜色与字体取自设计令牌。
- `showToast(message)`：在外壳底部显示简短确认；`downloadFile(content, name, type)` 让读者保存生成的文本文件，例如导出的记录或 CSV。
- `catalogSite(slug)` 与 `sites`：读取各专题 `site.json` 的信息（含分组 `group`），按 `order` 再按 slug 排序。
- `SiteBar`：全站顶栏，`current` 标出所在栏目（笔记、练习、案例、术语、复习），右侧打开全站搜索；`TopicShell` 的 `section` 把它传给顶栏。

专题运行时（`src/ui/topic/`，同样经 `@ui` 导入）承载每个专题共有的部分：

- `mountTopic(options)`：专题的唯一入口，见上表；`useTopic()` 在任何专题组件里返回 `{ slug, content, records }`，`useTopic<E>()` 标明专题自有记录字段的类型。
- `defineTopicContent(raw)`：校验 `content.json` 的共享核心（章节、块、预测、练习、术语、摘录、阅读指引、来源及它们之间的引用；同一校验由内容发布命令在事务内执行），返回带 `chapterById`、`excerptById`、`quizById`、`chapterPath`、`predictions`（全部预测及其记录 id）与 `dataOf(值或键)` 的内容，专题自有字段类型保留；章节默认路由为 `/<id>`，`content.json` 的顶层字段 `chapterRoute`（如 `"/chapters/{number}"`，只用 `{id}` 与 `{number}` 占位）可换成专题自己的路径，单章的 `path`（如地图章的 `"/map"`）优先于两者。
- 学习记录：`mountTopic` 经 API 建立，公共字段 `recent`（最近章节的 `{ chapter, opened }`，时间戳与笔记一致）、`complete`、`bookmarks`、`notes`、`answers`（按练习题 `id`）、`diagnostic`（起点自测，题目取自 `placement`，没有时取 `quiz`）、`predictions`（按预测 id，`{ option }`、`{ selected }`、`{ sets, choice? }`、`{ from, to, choice? }`、`{ value }` 或矩阵的 `{ cells }`，按该预测校验）；专题自有字段通过 `records: { 字段: { empty, parse } }` 注入并自行校验。`records` 对象提供 `records`、`storageError`、`toggle`、`retry`。
- 目录与路由：第一条是专题首页，其后章节按 `parts` 分组（只有一组时用 `label`）；每章由共享章节页按 `blocks` 渲染，首页展示全部章节与来源说明。
- `ChapterBody`（`id`：章节体，`ChapterBlocks` 按块目录渲染块序列，再接判断练习、原文区、阅读指引、本章来源与 `ChapterRecords`）、`ChapterBlocks`（`chapter`、`blocks`）、`ChapterPrediction`（`id` + `prediction`；`kind` 为 `choice`（默认）、`atoms`、`bonds`、`atom-set`、`arrows`；`molecules` 画在题目下，`context` 是题干补充，`excerpt` 随结果显示；首次提交写入 `records.predictions`，之后只显示结果）、`QuizQuestion`（`id`，`diagnostic` 写入起点自测；默认插槽放题目涉及的结构或图；题目有 `optionExplanations` 时逐项解释）、`ChapterRecords`、`TopicTerm`（正文中的术语，点开术语卡）、`TopicRefs`（句末来源编号，点开来源卡）；专题首页展示 `sourcesIntro`，章末资料来源按该章 `refs` 展示。
- `lab` 模型（`src/ui/models/catalog.ts`）：每个模型声明 `inputs`（`id`、`label`、`kind: "number"` 的 `min`/`max`/`step`/`unit`/`default`，可选 `control: "range"` 用滑块，或 `kind: "select"` 的 `options`/`default`）；输入可以是静态数组，也可以是 `inputs(data)`，统一经 `modelInputs(model, data)` 解析并调用模型可选的 `validateData(data)`。纯函数 `run(values, data)` 返回 `{ summary?, readouts?: [{ label, value }], charts?: [{ title?, xLabel, yLabel, points 或 series: [{ name, points, scatter? }], xDomain?, yDomain? }], tables?: [{ caption, columns, rows, note? }], revealed?: 同样四项 }`（`revealed` 只在读者按块的 `reveal` 按钮后显示），不能回答的输入组合抛出面向读者的信息；`tests/ui-lab-models.test.ts` 按每个专题的 `lab` 块（默认值、presets、data）运行对应模型，没被引用的模型按默认值运行一次，模型的数值由对应专题的 `tests/<slug>-models.test.ts` 核对。模型按专题组放在 `src/ui/models/<组>.ts`，在 `catalog.ts` 里登记一行。现有模型：`plate-capacity`（孔板容量）。
- 浏览器测试用 `tests/helpers/prediction.ts` 的 `expectBeforePrediction` / `expectAfterPrediction` 断言正文始终可见，题目的正确答案与解释只在作答后显示，并在刷新后恢复。

数据表与预测矩阵（`src/ui/data/`、`src/ui/matrix/`，同样经 `@ui` 导入）承载两类至少两个专题共有的交互。数据由 `define…` 函数校验后传给组件，坏数据在模块加载时抛错；演示见 `/showcase/data` 与 `/showcase/matrix`。

- `defineDataTable(input)` 与 `DataScatterExplorer`：来源印出的数值表，可排序、按组筛选、任选两列画散点，点一行用 `MoleculeView` 显示结构。`input` 有 `columns`（`key`、`label`、`unit` 显示单位、`sourceUnit` 来源单位、`shift` 小数点移位数、`scale` 为 `log` 或 `linear`、线性轴可给 `domain`）、可选的 `groups`（`label` 与 `items: [{ id, label, where? }]`，此时每行必须有 `group`）、可选的 `alternates`（见下）和 `rows`（`id`、第一列文字 `label`、详情与散点里的全名 `name`、`smiles?`、`group?`、`notes?`、`values: { 列key: { raw, sd?, alternate? } }`）。组件的 props：`table`、`title`、`label`（区域名）、`noun`（行的称呼，默认“行”）、`idLabel`（第一列表头）、`missing`（缺测格的文字，默认“未测”）、`defaultX` / `defaultY`；插槽 `default`（表上说明）、`after-plot`（属性 `x`、`y`、`use`，放专题自己的读数，例如相关系数）、`detail-caption`（属性 `row`）、`footer`。
  - 数值约定：`raw` 是来源印出的文字，解析为 `{ raw, op, value }`，`op` 为 `=`、`>` 或 `<`。界限值按界限处理：表里带符号显示，散点画空心三角（`>` 朝上、`<` 朝下）画在界线上，排序时排在同值的确切值之后（`<` 之前），统计只取 `op` 为 `=` 的值。缺测的格子没有这个 key，表里显示 `missing`，不进散点，更不补成 0；对数轴不画 0 与负值，线性轴可以画负值。`shift` 把来源单位换成显示单位，移动的是文字里的小数点，不做乘法。
  - 备选值：同一个格子另一处来源印了不同的值时，写在 `alternate: { raw, unit?, where, note? }`，`unit` 是该列的 `unit` 或 `sourceUnit`；`alternates` 给出表里的来源简称与单选项文字。表中并排显示，标出 `where`；散点用 `alternates.plot` 指定的那一种（`listed` 为列出的值，`alternate` 为备选值），读者可切换，用到备选值的点画虚线圈并用细线连到另一种写法的落点。约定：来源的表与已发表的主文不一致时，散点默认取已发表的主文值（`plot: "alternate"`），两个值都留在页面上，不替读者选一边。
  - 留在专题内：相关系数、倍数、哪些行“写法一致”这类统计与结论，用 `after-plot` 插槽接入；列的含义、单位换算以外的领域规则也由专题的 `columns` 与文案决定。
- `defineMatrix(input)` 与 `PredictionMatrix`：行是实验或化合物，列是候选，每格一个结论，带体系、图号表号与页码、原文引文。`input` 有 `rows`（`id`、`label`、`smiles?`）、`columns`（`id`、`label`、`full?`）、`outcomes`（`id`、`label`、`tone`、`choiceLabel?`、`summary?`；`tone` 取 `success`、`accent`、`danger`、`evidence`、`untested`，决定格子的底色）、`choices`（读者可选的 outcome `id`，按单选项顺序）、`required`（必答格 `行:列`）和 `cells`（`row`、`column`、`outcome`、`scope?`、`system?`、`evidence: [{ source, locator, quote? }]`、`caveat?`、`gap?`）。校验：每个行列交点恰好一格；`untested` 的格子必须写 `gap`，已测的格子至少一条 `evidence`；必答格的结论必须在 `choices` 里，而 `choices` 没有 `untested` 的选项（如“原文没测”）时，未测格子不能出题。未测永远显示为未测，不会被当成“否”。
  - props：`model`、`answers`（格子 id 到所选 `choices` 下标）、`question`（含 `{row}`、`{column}` 的题面模板）、`label`（矩阵的区域名）、`caption`、`rowHeader`，可选 `heading`、`instruction`、`quoteLang` 和 `part`（`questions`、`matrix` 或默认的 `both`）。必答格逐格先选后提交，提交后只展开该格的证据；全部答完才显示完整矩阵，每格可点开看体系、出处和引文，答过的必答格标“你猜对 / 你猜错”。事件 `@answer(id, 下标)` 与 `@reset(id)`；来源编号的显示由页面决定，插槽 `source`（属性 `id`）里放 `TopicRefs` 或别的内容，默认显示 `[id]`。
  - 组件不读写浏览器存储：`answers` 来自专题记录，事件写回记录。`matrixAnswersField(model, label?)` 返回 `mountTopic` 的 `records` 字段（存下标，非法的格子或下标整体拒绝），页面把 `records.<字段>` 传给 `answers`。章内要在提交前后插入自己的段落时用 `part`：`questions` 放在预测区，`matrix` 放在揭晓区，矩阵自身也只在答完后出现。

何时用共享件：数据是“行 × 若干数值列”并需要排序、筛选或两列对照，用 `DataScatterExplorer`；逐格带出处的“行 × 候选”结论表，并要读者先猜后揭晓，用 `PredictionMatrix`。留在专题内：数据不是数值（定性评级、整张表出自同一页而没有逐格引文）、需要共享件没有的控件（路线并排比较、相关系数）、或只有一个专题会用。先用共享件覆盖能覆盖的部分，其余通过插槽接入，不复制组件源码。

结构量距（`src/ui/structure/`，经 `@ui` 导入）承载“在真实坐标的子集上旋转、缩放、点两个原子量距离或点预设的接触”。数据同样由 `define…` 函数校验，坏数据在模块加载时抛错；演示见 `/showcase/structure`。

- `defineStructureSet({ fetchedOn, entries })` 与 `StructureLab`：`fetchedOn` 是坐标取自 RCSB 的 ISO 日期。每个条目有 `id`、`label`（多个条目时的页签文字）、`url`（同域路径，坐标文件由内容命令发布，拒绝外链）；`source`（`pdb` 四位 PDB 号、`title`、可选 `resolution`、`method` 默认“X 射线”、`note` 写论文与专题来源编号）；`subset`（`residues` 为保留的链及首末残基号，`hetero` 为保留的非聚合物 `{ chain, resn, resi, name? }`）；可选 `ligand`（`{ chain, resn, resi, name }`，须在 `hetero` 里，视图以它为中心打开）；`layers`；可选 `labels`；`presets`。条目可带专题自有字段，类型保留。
  - `layers`：绘制规则，按顺序叠加。`select` 为 `{ chain?, resi?, elem? }`，`resi` 是残基号或 `"536-547"` 这样的区间且需要 `chain`；`style` 为 `cartoon`、`stick`、`sphere`；`color` 为 `grey`、`blue`、`cyan`、`green`、`orange`、`magenta`、`yellow`；可选 `radius`、`opacity`；有 `label` 的图层进图例（“灰：…；球：…”）。
  - `labels`：`{ chain, resi: [...] }`，视图里标出这些残基并给一个开关，文字取自坐标（如 W380）。
  - `presets`：`id`、`label`、`a`、`b`（`{ chain, resi, atom }`，两个原子必须在本条目的坐标子集里，否则加载时报错并指出是哪个预设）、可选 `expect`（页面文字引用的距离，Å）。按钮上的数值由坐标算出，`expect` 只供单测核对。
- props：`set`（`defineStructureSet` 的返回值）、可选 `ids`（要提供的条目及其顺序，默认全部；多于一个时出页签）。插槽 `readout({ entry, atoms })` 在预设按钮下方，放专题自有读数，例如配体各部分的 B 因子（用 `@ui` 的 `meanB`）。组件没有事件，也不读写浏览器存储。
- `structure-lab` 是独立的章节内容，预设与距离读数从打开章节起可见。预测题的题面只提供作答所需信息，答案与解释放在题目结果区。
- 纯逻辑 `pdb.ts`（`parsePdb`、`findAtom`、`distance`、`nearestAtom`、`residueAtoms`、`meanB`）与 `model.ts`（`presetDistances`、`verifyStructure`）不依赖 `@ui`，`node --test` 可直接导入。内容制作时对每个条目运行 `verifyStructure(entry, parsePdb(坐标文本))`：保留的链与范围同声明一致、`hetero` 与配体存在、无氢无水、每个图层与标签选得到原子、每个预设的两个原子各恰好命中一个、`expect` 与坐标算出的距离相差不超过 0.005 Å。
- 取子集的脚本留在专题：把 `toolbox/structure/extract-subset.ts` 复制到内容工作目录的 `sites/<slug>/tools/` 改写，脚本头记录来源 PDB 号、链、残基、取数日期和完整文件的 SHA-256，输出文件头写 REMARK。坐标文件放在内容目录的 `static/`，随内容快照发布。
- 只在单个条目内量距。几个结构之间的位移（例如各结构里同一段螺旋的参照原子）要先叠合：专题脚本叠合并把变换后的坐标写进各自的子集（文件头 REMARK 注明），位移用 `pdb.ts` 的函数在专题模型里算，数值在发布前核对。

专题通过 `structure-lab` 块引用 `content.json` 的结构集合，每个条目在 `url` 中指定已发布资源的路径：

```json
{
  "type": "structure-lab",
  "set": "structures",
  "ids": ["181L"]
}
```

结构集合放在 `data.structures`，字段遵循上面的 `defineStructureSet` 契约。共享组件实现与样式用法参考 `src/showcase/`。正文、提示、图表与实验由块目录组合。

科学计算、单位和输入边界由 `src/ui/models/` 的共享模型与内联样本单测负责；专题提供模型参数、数据和证据解释。新增交互先确认两个真实用例，再扩共享块目录。API 记录校验与写入失败反馈由 `createTopicRecords` 统一处理。

## 制作工具

| 任务               | 使用入口                                                                                                    | 页面产物                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 创建独立专题       | `npm run site:new -- <slug> "<title>" "<description>" <group>`                                              | 内容工作目录中的专题单元     |
| 图片查看           | `UiFigure`                                                                                                  | 带图注的可放大本地素材       |
| 分步图示           | `src/showcase/StepScene.vue` 的示例与 Vue SVG、Motion                                                       | 可控制步骤的 SVG 图示        |
| 定量曲线           | `LineChart`                                                                                                 | 页面公式生成的数据与可读图表 |
| 数学与化学式       | `Formula`，按需启用 mhchem                                                                                  | 公式及文字解释               |
| 二维分子结构       | [二维结构 recipe](recipes/molecule-2d.md) 与 `toolbox/molecule-2d/render.py`                                | 来源可核对的 SVG             |
| 蛋白或配体三维结构 | [三维结构 recipe](recipes/protein-3d.md)，`StructureLab`（量距）与 `src/showcase/ProteinViewer.vue`（旋转） | 按需加载的结构查看器         |
| 资料书架查询       | `python3 -I scripts/material.py`                                                                            | 原文页图、章节文字与引用渲染 |
| 文字自检           | `node scripts/prose-check.ts [slug]`                                                                        | 免责式转折、套话与长句清单   |
| 固定讲解视频       | [视频 recipe](recipes/explainer-video.md) 与 `npm run video:render`                                         | 嵌入章节的视频               |

每个正式页面在内容工作目录的 `sites/<slug>/` 内保存其用户路径、内容依据、所用素材与数据、图示假设和验收方法。文字与图示表达同一来源。分步动画先确定静态关键帧及每帧含义，再添加过渡；参数模拟先确定计算函数和单位，再绘图。

示例页的二维结构使用 RDKit 生成的乙醇 SVG；三维结构使用 RCSB PDB 1CRN 坐标；视频使用中性 A/B 动画。这些示例证明制作与嵌入路径可运行，具体科学解释仍由专题内容和来源决定。

完整的块用法见中性样本 `tests/fixtures/content/sites/`：`sample` 与 `instruments` 覆盖学习型专题，`fable-patent` 覆盖专利数据块。
